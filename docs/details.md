# 研究の詳細

## データと Step 1: 時系列の構築

- 元データ: F-DATA（富岳ジョブスケジューリングログ、2021-03〜2024-04）
- ジョブの実行区間を1時間バケットへ秒単位で按分し、多変量時系列を構築した
- 期間: 28,084時間（2021-03-01 00:00 〜 2024-05-14 03:00 JST）
- 主ターゲット: `power_consumption`（按分消費電力の合計）
- その他の特徴量: 平均同時稼働ノード数、平均同時実行ジョブ数、到着数、待ち時間、失敗率など

妥当性チェックとして、平均同時稼働ノード数の最大値が 158,886 で、
富岳の総ノード数 158,976 に近いことを確認した。

## Step 2: モデル比較

比較したモデルは7つである。

|  | 電力のみ（②） | +covariate（③） |
|---|---|---|
| LightGBM | ②-LightGBM | ③-LightGBM |
| LSTM | ②-LSTM | ③-LSTM |
| TFT-lite | ②-TFT-lite | ③-TFT-lite |
| Chronos-bolt-small（zero-shot） | ①（参照点） | — |

- 同一の train / valid / test、同一の評価ウィンドウ、同一の評価指標で比較した
- Chronos は `amazon/chronos-bolt-small` を zero-shot で使用し、CPUで推論した
- コンテキストは直近720時間に統一した

全体の MASE（v2）は、Chronos 0.654、LightGBM（+covariate）0.771 である。
horizon 別では、短期（1–24h）は Chronos が最良、
中期（48–168h）は LightGBM が安定期・遷移期を問わず上回った。

## Step 3: レジーム遷移期の評価

- test 期間内に高感度な変化点検出を行い、4つの変化点を検出した
  - 2023-04-04, 2023-05-14, 2023-08-16, 2023-10-05
- ±14日を遷移期として再ラベル付けし、7モデルを再評価した
- 中期での LightGBM 優位は、安定期・遷移期のどちらでも確認された
- covariate の追加効果は、遷移期ではなく安定期でこそ見られた
  - この傾向は v1 と v2 の2つの分割設計で独立に再現した

## Step 4: covariate の重要度分析

- LightGBM③ の SHAP 分析と、TFT-lite③ の Variable Selection Network で分析した
- 全体では `power_consumption` のラグ・rolling 特徴量群が支配的で、
  covariate 群の寄与は |SHAP| 合計の約19.1% であった
- 遷移期で重要度が最も上がったのは
  `avg_wait_time_sec_z168h`（待ち時間の週内急増 z-score）で、1.65倍であった
  - v1 では 1.70倍であり、分割設計を変えても同じ方向で再現した
- 実務的な示唆として、待ち時間の急増はレジーム遷移の先行指標になりうる

## Step 5: 意思決定シミュレーション

- 分位点予測を、冷却容量・電力バジェットの引当問題に接続した
- newsvendor 型の非対称コストで評価した
- 全体では Chronos が最良で、予測なしの static 方式と比べて
  最大33.6%のコスト削減効果が見られた
- ただし中期では Chronos は static より高コストになり、
  モデルと horizon の組み合わせを誤ると予測しない場合より悪化しうる
